## 2. The collector

| Item | What we built |
|---|---|
| Script | `collector/Collect-CCREvidence.ps1`, Windows PowerShell 5.1, no modules, no internet, ASCII |
| Reads (slide 8) | hostname, serial, MAC, make/model, OS build + UBR, installed updates, BitLocker, Secure Boot, TPM, EDR agents and service state (9 products by service name; Defender for Endpoint also needs OnboardingState 1), Defender AV, Security Center AV, firewall profiles, local Administrators, `net accounts` policy, screen lock, domain / Entra join (`dsregcmd`) |
| Never reads | files, documents, email, browser data, credentials, user content, Gavel |
| Without admin | falls back to the shell's BitLocker view, the registry for Secure Boot, PnP for TPM; the bundle records `elevated: false` and the portal warns |
| `-Preview` | prints the facts, writes nothing, so county IT can review before running |
| Output | `<PC>_<UTC time>.ccre`, next to the script or on the Desktop. Nothing else is written; nothing keeps running |

**Bundle format** (`backend/app/collector/bundle.py` documents it exactly):

```
K   = 64 random bytes                    mac_key = K[:32], enc_key = K[32:]
ek  = RSA-OAEP-SHA-256(office public key, K)
ct  = AES-256-CBC(enc_key, iv, PKCS#7(facts JSON))
tag = HMAC-SHA-512(mac_key, aad || iv || ct || bitlen(aad) as uint64 BE)[:32]
aad = "ccr-bundle/1|<office id>|<key ARN>"
```

This is JWE's A256CBC-HS512 composition. We used it because .NET Framework, which Windows
PowerShell 5.1 runs on, has no AES-GCM.

**Keys.** Each office has a KMS RSA-3072 `ENCRYPT_DECRYPT` key, created with the office's raw key
from `tenant_ids`. Only the portal role may call `GetPublicKey`, and only the portal may call
`kms:Decrypt`, pinned to `RSAES_OAEP_SHA_256`. Admins manage the key but cannot use it (R4).

**Download and tokens.** Each download is a row in `collector_download`. Its id is the token in
`office.json`, and the bundle carries it inside the encrypted content.
- On upload, the portal refuses a bundle in these cases:
  - wrong office or key;
  - altered (tag mismatch);
  - token never issued or revoked;
  - duplicate (SHA-256);
  - collection time in the future.
- It warns, without refusing, when the bundle is over 30 days old or was collected without admin.

**Signing.**
- `scripts/sign-collector.sh` runs in CodeBuild before the final `docker build`. It signs with
  jsign 7.5 (Apache-2.0, sha256-pinned) through a KMS RSA-3072 `SIGN_VERIFY` key that only the
  build role may use, pinned to PKCS#1 v1.5 SHA-256 (R3, R4). The signature carries a DigiCert
  RFC 3161 timestamp.
- The certificate is self-signed for the lab, made once by `app.collector.codesign` (kms:Sign
  over the TBS) and kept in the build bucket:
  - `CN=CCR Evidence Collector (lab, self-signed)`
  - thumbprint `7558E7C7C185D24D13160A72F99C29F6C1C0B608`, valid to 25 Oct 2028.
- Verified on Windows:
  - `Get-AuthenticodeSignature` shows the signer, the Code Signing EKU and the timestamp, and
    reports the root as untrusted (expected);
  - a one-line change gives `HashMismatch`.

**Intake.** The portal decrypts at upload and stores:
- the bundle bytes as uploaded in `import_file` (template `collector`);
- the device in `device_observation` (source `collector`), with the full facts under
  `attributes.collected`.

The Devices page expands a collected PC to show those facts.

## 4. Known limits

- Anyone holding a download's `office.json` can write bundles for that office: the public key
  is public by design. What limits this is the token: every bundle traces to a download, and a
  leaked download can be revoked. Proof that a bundle came from a particular PC would need a
  per-device key, which we chose not to add.
- Intake runs in the portal, not behind the evaluator's fence (R6), so staff get an answer at
  upload. The bundles are kept as uploaded, so intake can be replayed behind the fence later.
- **Live test, 26 Oct:** Naresh downloaded the collector and ran it on his laptop, then
  uploaded three sample CSVs and one bundle. All four loaded; the portal opened the bundle with
  the real KMS key.
- **Execution policy found in that test:** D-Biz laptops set `RemoteSigned` by Group Policy
  (UserPolicy). That overrides `-ExecutionPolicy Bypass`, so the downloaded script (it carries
  the mark of the web) was refused because the lab root isn't trusted. Counties with a similar
  policy will hit the same thing until we have a commercial certificate. The README in the zip
  now explains it. We ran the identical local copy for the test, which RemoteSigned allows.
- Windows only. The EDR catalogue is by service name; unknown agents show as "none".
- `net accounts` output is parsed in English.
