# HANDOFF-22-10-2026.md: SCuBA (ScubaGear) alignment

For Tim Hill and the AI assistant he uses. Written 22 October 2026 by D-Biz (Naresh Pamukuntla).
Follows `HANDOFF-TIM.md` (19 Oct 2026, state of the build). Read that first; this file covers only
what changed since: findings and scoring are now aligned to CISA ScubaGear (SCuBA baselines).

## 1. Summary

ScubaGear is the approved assessment tool, so the platform now scores Microsoft 365 the way
ScubaGear does. It does not run ScubaGear inside the platform: ScubaGear needs a certificate private
key in the Windows certificate store (breaks R3), Global Reader plus write-capable
`Sites.FullControl.All` / `Exchange.ManageAsApp` for full coverage (breaks R7), and Windows
PowerShell 5.1 (breaks R8). Instead:

- **A. Entra ID, collected:** our worker reads Graph with the KMS-signed credential (as before), the
  fenced evaluator rebuilds ScubaGear's exact input and runs **ScubaGear's own Rego rules (v1.8.0,
  unmodified) with OPA 1.15.2**. Result: the same Pass / Fail / Warning / N/A per `MS.AAD.*` policy.
- **B. Other products, imported:** the county runs ScubaGear itself and uploads `ScubaResults_*.json`
  (onboarding step 5). Exchange, Defender for Office 365, SharePoint, Teams, Power Platform,
  Power BI. Labelled Imported, with tool version and date; tenant must match the consented tenant.

**Verified:** side by side with a real ScubaGear 1.8.0 run on the same CDX tenant, **30 of 30 Entra
policies identical** (16 Fail, 5 Warning, 6 Pass, 3 N/A on both).

## 3. IRMA ↔ SCuBA mapping (please review)

| IRMA control | Required (fail → Gap) | Advisory (fail → Weak) |
|---|---|---|
| 1 MFA on remote access | MS.AAD.3.2v1, MS.AAD.1.1v1 | MS.AAD.3.1v1, MS.AAD.3.5v1, MS.AAD.3.9v1 |
| 2 MFA for third parties | MS.AAD.3.2v1 (guest exclusions checked inside) | MS.AAD.8.1v1, 8.2v1, 8.3v1 |
| 3 MFA for privileged accounts | MS.AAD.3.6v1 | MS.AAD.3.5v1, MS.AAD.7.1v1 – 7.9v1 |
| 4–8 | no SCuBA equivalent (backups, EDR, DR, training) | — |

A required policy in Error or N/A makes the control Not observed, and then the earlier Graph reading
is shown instead, with the reason. Consequence worth noting: SCuBA treats a **report-only** MFA policy
as not enforced, so Lab County A's control 1 moved from Weak to **Gap**.

## 4. Permissions (consent grows from 5 to 10, all read-only)

Added: `Directory.Read.All`, `User.Read.All`, `PrivilegedAccess.Read.AzureADGroup`,
`PrivilegedEligibilitySchedule.Read.AzureADGroup`, `RoleManagementPolicy.Read.AzureADGroup`.
Existing: `Policy.Read.All`, `RoleManagement.Read.Directory`, `AuditLog.Read.All`, `Device.Read.All`,
`LicenseAssignment.Read.All`. These are exactly ScubaGear's own Entra scopes plus our original reads
(confirmed: ScubaGear's interactive sign-in requested the same 7 Entra scopes). No Global Reader, no
Exchange, no SharePoint permission. Every county's consent page and evidence record must disclose the
wider reach (`Directory.Read.All`, `User.Read.All`).

## 6. Known limits

- ScubaGear ships rule updates with each release. We add the new version's Rego in a new folder and
  re-run the side-by-side test before switching; v1.8.0 is pinned today.
- Imported reports are the county's own run: we verify tenant id and record a SHA-256 of the file,
  but cannot prove it was unaltered. They stay labelled Imported.
- Running ScubaGear on a managed Windows laptop: WAM/browser sign-in may refuse other tenants'
  accounts; the workaround is a device-code token passed to `Connect-MgGraph -AccessToken`, then
  `Invoke-SCuBA -LogIn $false`.
